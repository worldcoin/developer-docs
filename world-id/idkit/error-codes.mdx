## Optional error reasons

An error code describes the broad failure. An optional `reason` provides more specific context. IDKit decodes it automatically into the generic `ErrorReason` type; no separate parsing function is required. Reasons can accompany different error codes, so handle the code and reason independently.

For example, World App can send this decrypted bridge response:

```json
{
  "error_code": "challenge_failed",
  "reason": "face_challenge_mismatch"
}
```

JavaScript `pollOnce()` returns:

```json
{
  "type": "failed",
  "error": "challenge_failed",
  "reason": "face_challenge_mismatch"
}
```

`pollUntilCompletion()` returns the same `error` and optional `reason`, with `success: false` instead of `type: "failed"`.

### Parsing behavior

| Bridge `error_code` | Bridge `reason` | Parsed error | Parsed reason |
| --- | --- | --- | --- |
| `challenge_failed` | `face_challenge_mismatch` | `challenge_failed` | `face_challenge_mismatch` |
| `user_rejected` | `user_cancelled` | `user_rejected` | `user_cancelled` |
| `connection_failed` | `network_error` | `connection_failed` | `network_error` |
| `challenge_failed` | An unrecognized string or `""` | `challenge_failed` | `unknown` |
| An unrecognized code | `network_error` | `generic_error` | `network_error` |
| `challenge_failed` | Missing or `null` | `challenge_failed` | Absent |

A missing or `null` reason stays absent; it does not become `unknown`. A reason must be a string or `null`; other JSON types are malformed. Never require a reason to handle a failure: app versions and failure paths can omit it, and SDK-generated errors such as a polling timeout do not have one.

The same parsing applies to v4 protocol errors: `reason` sits alongside `error` in a raw proof response, or inside `proof_response` in a wrapped response. Waiting and successful proof results do not include an error reason. JS mini-app error responses also preserve the optional reason.

### SDK surfaces

| SDK surface | Reason field or value |
| --- | --- |
| JavaScript failed `Status` and `IDKitCompletionResult` | `reason?: ErrorReason`; absent reasons are omitted from the returned object |
| React hooks | `errorReason: ErrorReason \| null` |
| React widget `onError` | Optional third argument: `onError(errorCode, debugReport?, reason?)` |
| Rust `Status::Failed` and UniFFI `StatusWrapper::Failed` | `reason: Option<ErrorReason>`; absent reasons are `None` |
| Swift `IDKitStatus.failed` and `IDKitCompletionResult.failure` | `reason: ErrorReason?`, default `nil` |
| Kotlin `IDKitStatus.Failed` and `IDKitCompletionResult.Failure` | `reason: ErrorReason?`, default `null` |

`ErrorReason` is a string union in JavaScript/TypeScript and an enum in Rust and the native SDKs. Unrecognized strings become `unknown` in JS, `ErrorReason::Unknown` in Rust, `.unknown` in Swift, and `ErrorReason.UNKNOWN` in Kotlin.

The following are the recognized wire strings. The `face_challenge_*` values refer to the challenge image; `face_selfie_*` refers to the live selfie.

| `age_below_threshold` | The estimated age is below the required threshold. |
| `username_mismatch` | The requested username does not match the user. |
| `biometric_rejected` | Device biometric authentication failed or was locked out. |
| `user_cancelled` | The user cancelled or closed the flow. |
| `proof_failed` | Proof generation failed. |
| `credential_unavailable` | The required credential is unavailable. |
| `pcp_missing` | The personal custody package containing enrolled face data is missing. |
| `face_auth_unavailable` | Face authentication is unavailable or its configuration was rejected. |

## Handling errors

Widgets expose `onError(errorCode, debugReport?, reason?)`. Hooks expose `isError`, `errorCode`, and nullable `errorReason` on the result object.

In JS and React, failed requests expose an `IDKitDebugReport` for triage. The widget `onError` callback receives it as a second `debugReport` argument for flow/bridge errors (host-app verify failures such as `failed_by_host_app` omit it); hooks expose `getDebugReport(): IDKitDebugReport | undefined`.

Treat version availability errors such as `world_id_4_not_available` and `world_id_3_not_available` as terminal for the current user and request. Retrying the same request usually returns the same result; change the requested credential policy or show a user-facing fallback instead.

In JS and React, match these with `IDKitErrorCodes`. Kotlin and Swift expose the same raw values through their `IDKitErrorCode` enums.

```tsx
<IDKitRequestWidget
  // ...
  onError={(errorCode, debugReport, reason) => {
    console.error("IDKit error", errorCode, reason, debugReport);
  }}
/>
```

```tsx
const flow = useIDKitRequest({ /* ... */ });

if (flow.isError) {
  console.error(flow.errorCode, flow.errorReason, flow.getDebugReport());
}
```
