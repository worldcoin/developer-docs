Use `MiniKit.sendTransaction()` to submit one or more World Chain transactions.

<Note>
  These examples assume MiniKit has already been initialized through
  `MiniKitProvider` or `MiniKit.install()`.
</Note>

## Availability

- Works natively in World App
- Supports Wagmi execution outside World App
- Batch transactions are only available in World App

## Basic Usage

```tsx
import { MiniKit } from "@worldcoin/minikit-js";
import type {
  CommandResultByVia,
  MiniKitSendTransactionOptions,
  SendTransactionResult,
} from "@worldcoin/minikit-js/commands";

export async function sendTransaction() {
  const input = {
    chainId: 480,
    transactions: [
      {
        to: "0x9Cf4F011F55Add3ECC1B1B497A3e9bd32183D6e8",
        data: "0x1234",
      },
    ],
  } satisfies MiniKitSendTransactionOptions;

  const result: CommandResultByVia<SendTransactionResult> =
    await MiniKit.sendTransaction(input);

  console.log(result.data.userOpHash);
}
```

<Warning>
  If you are integrating through Wagmi, viem, or ethers with the World App
  EIP-1193 provider, the standard `eth_sendTransaction` call resolves to the
  MiniKit `userOpHash`, not a canonical transaction hash. Do not treat the
  returned value as a final transaction hash or pass it directly to
  `waitForTransactionReceipt`. If you need the final on-chain transaction hash,
  resolve the user operation status first.
</Warning>

## Confirming the User Operation

Use `userOpHash` to wait for completion. For React apps, `@worldcoin/minikit-react`
exports `useWaitForUserOperationReceipt`, which polls the Developer Portal
user-operation endpoint until the transaction hash is available.

```tsx
import { useWaitForUserOperationReceipt } from "@worldcoin/minikit-react";
import { createPublicClient, http } from "viem";
import { worldchain } from "viem/chains";

const client = createPublicClient({
  chain: worldchain,
  transport: http("https://worldchain-mainnet.g.alchemy.com/public"),
});

const { isLoading, isSuccess } = useWaitForUserOperationReceipt({
  client,
  userOpHash,
});
```

If you are not using React, poll the Developer Portal endpoint directly:

- [GET /api/v2/minikit/userop/{user_op_hash}](/api-reference/developer-portal/get-user-operation)

```ts
const response = await fetch(
  `https://developer.world.org/api/v2/minikit/userop/${userOpHash}`,
);
const status = await response.json();

if (status.status === "success") {
  console.log(status.transaction_hash);
}
```

This endpoint returns the final `transaction_hash` when it is available and
does not require an `app_id`.

## Fallback Behavior

- `executedWith: "wagmi"` is the standard web execution path
- multi-transaction batching does not work in Wagmi mode
- custom `fallback` is available if you need non-Wagmi behavior
- use `userOpHash` as the polling key in both MiniKit-native and Wagmi paths

## Notes

- `chainId` must be `480`
- the public v2 API uses `transactions`, not the old `transaction` field
- the public v2 result exposes `userOpHash`, not `transaction_id`
- `eth_sendTransaction` on the World App provider also resolves to `userOpHash`

## Error Codes

| Code | Meaning |
| --- | --- |
| `invalid_operation` | The requested operation is not allowed |
| `user_rejected` | The user rejected the request |
| `input_error` | The payload is invalid |
| `simulation_failed` | Simulation failed before execution |
| `transaction_failed` | The transaction failed after submission |
| `generic_error` | Unexpected failure |
| `disallowed_operation` | The requested operation is disallowed |
| `validation_error` | Validation failed before execution |
| `invalid_contract` | The contract is not allowed for your app |
| `malicious_operation` | The operation was flagged as malicious |
| `daily_tx_limit_reached` | Daily transaction limit reached |
| `permitted_amount_exceeds_slippage` | Permit2 amount exceeds allowed slippage |
| `permitted_amount_not_found` | Permit2 amount could not be resolved |
