World IdP is the World ID OpenID Connect (OIDC) provider. When a user authenticates with World ID, World IdP returns a signed authentication result and a sector-scoped account identifier (`sub`). Your application owns its accounts, sessions, permissions, and actions.

Use World ID Auth when you want a standard OIDC integration for:

- Primary sign-in with World ID.
- Step-up authentication before sensitive actions, while you keep your existing sign-in.
- Human checkpoints in agent workflows.
- Authorizing access to your MCP server.

An existing auth server can act as the OIDC client.

## Choose your integration

[Set up your client](/world-id-auth/client-setup) first, then follow the path for your application.

| Goal | Guide |
| --- | --- |
| Authenticate through a browser | [Authorization Code Flow](https://auth.world.org/docs/guides/oidc#sign-in-through-the-browser) |
| Authenticate a CLI or client without a browser callback | [Device Authorization Grant](https://auth.world.org/docs/guides/oidc#sign-in-a-headless-agent-device-flow) |
| Require recent or specific authentication before an action | [Step-up authentication](https://auth.world.org/docs/guides/step-up) |
| Pause an agent workflow for a human checkpoint | [Human checkpoints](https://auth.world.org/docs/guides/step-up#human-checkpoints) |
| Use World ID for your application's primary sign-in | [Primary sign-in](https://auth.world.org/docs/guides/oidc#primary-sign-in) |
| Authorize access to your MCP server | [MCP authorization](https://auth.world.org/docs/guides/mcp-authorization) |
| Accept delegated access through an XAA-capable host | [Cross-App Access (XAA)](https://auth.world.org/docs/guides/xaa) |

The [tokens and identity reference](https://auth.world.org/docs/guides/id-token) defines subjects and authentication claims. It also lists the [credentials and authentication classes](https://auth.world.org/docs/guides/id-token#credentials-and-authentication-classes) your application can accept. To allow either Orb or Selfie Check, list both classes in your [authentication request](https://auth.world.org/docs/guides/step-up#accept-orb-or-selfie-check).

Before launch, complete the checks in [Sandbox and testing](/world-id-auth/testing).

## Environment values

| Setting | Production | Sandbox |
| --- | --- | --- |
| Issuer | `https://auth.world.org` | `https://sandbox.auth.world.org` |
| Discovery | `https://auth.world.org/.well-known/openid-configuration` | `https://sandbox.auth.world.org/.well-known/openid-configuration` |
| Developer portal | [Portal](https://auth.world.org/portal) | [Sandbox portal](https://sandbox.auth.world.org/portal) |

Use registration, credentials, and discovery from the same environment. The [authentication profile](https://auth.world.org/docs/guides/oidc#configure-your-oidc-library) lists supported scopes, grants, signing algorithms, and client requirements.

Most OIDC libraries configure themselves from the discovery document:

```bash
curl https://auth.world.org/.well-known/openid-configuration
```

## Other World ID integrations

World ID Auth covers OIDC integration with World IdP. Use World IdP registrations, credentials, and identifiers only for that flow. [IDKit](/world-id/idkit/integrate) proof applications use their own.

- **IDKit uniqueness:** use a nullifier scoped to the application and action for one-use eligibility. Verify the proof on your backend and atomically reject a previously consumed nullifier. Check authentication freshness separately from stored uniqueness results. Follow the [IDKit integration guide](/world-id/idkit/integrate).
- **IDKit sessions:** use repeated proofs of the saved `session_id` for account continuity. Each check still requires user interaction and a fresh proof. Use `session_nullifier` to identify a proof for replay checks. Manage application login cookies and World IdP browser sessions separately from proof sessions. Follow the [session proofs guide](/world-id/idkit/session-proofs).

<Warning>
  Legacy Sign in with World ID is deprecated. Use the World IdP OIDC flow for new sign-in integrations. Legacy credentials and identities are not interchangeable with World IdP credentials and identities.
</Warning>

OIDC authentication is repeatable. For one-use benefits, enforce your own rule with atomic consumption in the [appropriate identity scope](https://auth.world.org/docs/guides/id-token#store-and-match-sub). Validate the resulting assurance and check business permissions in your application.
