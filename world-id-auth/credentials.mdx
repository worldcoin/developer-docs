World ID Auth is World's OpenID Connect (OIDC) provider. Your app signs people in with a standard OIDC authorization request. The ID token reports which credential the person used through the `acr` (authentication context class) and `amr` (authentication methods) claims.

## Credentials and authentication classes

A World ID account can hold Orb and Selfie Check credentials, plus passkeys for authentication.

| Credential | What it establishes | Baseline `acr` |
| --- | --- | --- |
| [Orb](/world-id/credentials/1) | Iris-based verification at an Orb provides high assurance of unique humanness. | `https://world.org/oidc/acr/orb` |
| [Selfie Check](/world-id/credentials/11) | Camera-based liveness and facial similarity checks provide a medium-assurance signal of humanness and uniqueness. Duplicate-account risk is higher than with Orb. | `https://world.org/oidc/acr/selfie` |
| Passkey | Authenticates control of the account with WebAuthn user verification. It adds no biometric uniqueness verification. | The account's Orb or Selfie Check class, or no `acr` if it holds neither. |

Choose according to the consequences of accepting a duplicate account. Selfie Check does not provide a strict one-person-one-account guarantee.

To add a face check during authentication, request `https://world.org/oidc/acr/orb-face` or `https://world.org/oidc/acr/selfie-face`. A passkey cannot satisfy either `-face` class.

## Accept Orb or Selfie Check

Selfie Check is only offered to apps that request a Selfie Check class. To accept either credential, add the `claims` query parameter to your authorization request. Set it to the following JSON and let your OIDC library URL-encode it:

```json
{
  "id_token": {
    "acr": {
      "essential": true,
      "values": ["https://world.org/oidc/acr/orb", "https://world.org/oidc/acr/selfie"]
    }
  }
}
```

The values are alternatives, so one matching class is enough. After you validate the ID token, check that its `acr` exactly matches one of the values you accept.

## Selfie Check sybil score at sign-up

Each Selfie Check proof carries a `sybil_score` from 0 to 10. A higher score means more similar faces are already enrolled. See [Understanding Sybil Score](/world-id/credentials/11#understanding-sybil-score) for how World calculates it.

World ID Auth checks the score only when a Selfie Check credential is new to World ID Auth:

- **Sign-up:** A Selfie Check credential that no account holds yet creates an account only if its score is at or below World ID Auth's maximum.
- **Connecting a credential:** Adding a new Selfie Check credential to an existing account on the Credentials page uses the same limit.
- **Returning sign-ins:** A credential that an account already holds skips the check. This includes reconnecting it on the Credentials page.

World ID Auth skips the check for returning credentials because World recalculates the score at each 90-day credential renewal. The score can rise after a lookalike enrolls, and checking it at every sign-in could lock out an honest account.

When a new credential's score is too high, World ID Auth stops the sign-in. The person sees **Selfie Check unavailable** with the instruction **Verify with Orb to continue**. Your app does not receive an ID token for that attempt. If your app accepts Orb, the person can sign in after they [verify at an Orb](https://world.org/find-orb).

<Note>
  Only the app integrity attestation authenticates the score. If World ID Auth cannot verify that attestation, it does not accept a new Selfie Check credential. The World ID app retries the request instead. Returning accounts still sign in.
</Note>
