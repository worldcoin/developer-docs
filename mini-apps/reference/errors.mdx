This page is a reference for error codes returned by current MiniKit commands.

<Note>
  World ID verification is no longer handled by MiniKit. Use
  `@worldcoin/idkit` for verification flows.
</Note>

## Pay

| Code | Meaning | Typical fix |
| --- | --- | --- |
| `input_error` | The payment request is invalid | Check the payload and try again |
| `user_rejected` | The user rejected the payment request | Ask the user to retry |
| `payment_rejected` | The user cancelled the payment in World App | Ask the user to retry |
| `invalid_receiver` | The recipient address is invalid or not allowed | Whitelist the correct receiver in the Developer Portal |
| `insufficient_balance` | The user does not have enough balance | Ask the user to fund the wallet |
| `transaction_failed` | The payment failed after submission | Retry or inspect the transaction on-chain |
| `generic_error` | Unexpected failure | Retry and inspect logs |
| `user_blocked` | Payments are blocked in the user's region | Do not continue with the payment flow |

## Send Transaction

| Code | Meaning | Typical fix |
| --- | --- | --- |
| `invalid_operation` | The requested operation is invalid | Check the transaction payload and method being called |
| `user_rejected` | The user rejected the transaction | Ask the user to retry |
| `input_error` | The payload is invalid | Validate `chainId`, `transactions`, and encoded calldata |
| `simulation_failed` | Simulation failed before execution | Inspect the simulation or debug URL and fix the transaction |
| `transaction_failed` | Submission succeeded but execution failed | Retry or inspect the user operation result |
| `generic_error` | Unexpected failure | Retry and inspect logs |
| `disallowed_operation` | The operation is not allowed | Remove approvals, admin actions, or other blocked calls |
| `validation_error` | Validation failed before execution | Check transaction structure and allowed contracts |
| `invalid_contract` | The contract is not allowed for your app | Whitelist the contract in the Developer Portal |
| `malicious_operation` | The operation was flagged as malicious | Remove the flagged behavior |
| `daily_tx_limit_reached` | The user hit the daily send-transaction limit | Wait until the next day |
| `permitted_amount_exceeds_slippage` | Permit2 spend amount violates the allowed slippage | Spend at least 90% of the permitted amount |
| `permitted_amount_not_found` | Permit2 amount could not be resolved | Check the Permit2 payload |

## Sign Typed Data

| Code | Meaning | Typical fix |
| --- | --- | --- |
| `invalid_operation` | The typed-data operation is invalid | Check the EIP-712 payload |
| `user_rejected` | The user rejected the request | Ask the user to retry |
| `input_error` | The typed-data payload is invalid | Validate `types`, `primaryType`, `message`, and optional domain fields |
| `simulation_failed` | Validation or simulation failed before signing | Inspect the typed-data payload |
| `generic_error` | Unexpected failure | Retry and inspect logs |
| `disallowed_operation` | The operation is not allowed | Remove the disallowed payload or flow |
| `invalid_contract` | The referenced contract is not allowed | Check the contract configuration |
| `malicious_operation` | The operation was flagged as malicious | Remove the flagged behavior |

## Request Permission

| Code | Meaning | Typical fix |
| --- | --- | --- |
| `user_rejected` | The user rejected the permission request | Ask the user to retry |
| `generic_error` | Unexpected failure | Retry and inspect logs |
| `already_requested` | The permission request is already in progress | Avoid issuing duplicate requests |
| `permission_disabled` | The permission is disabled on the device or in World App | Ask the user to enable it in settings |
| `already_granted` | The permission has already been granted | Skip the prompt and continue |
| `unsupported_permission` | The requested permission is not supported | Request a supported permission only |

## Attestation

| Code | Meaning | Typical fix |
| --- | --- | --- |
| `unauthorized` | The app is not authorized to request this attestation | Check app configuration and credentials |
| `attestation_failed` | The attestation request failed | Retry and inspect backend logs |
| `integrity_failed` | Integrity checks failed for the request | Recompute the request hash and payload |
| `invalid_input` | The request hash or payload is invalid | Validate the attestation input |
| `unsupported_version` | The host app does not support this attestation version | Update World App |

## Close Mini App

`closeMiniApp()` does not define command-specific error codes. If it fails, the usual cause is environment setup, such as calling it before `MiniKit.install()` or on an unsupported World App version.
