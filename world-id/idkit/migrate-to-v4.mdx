<Note>
Disclaimer: IDKit v4 does't mean you're upgrading to World ID 4.0 the SDK version is independent of the World ID protocol version. 

In IDKit v4, we introduced breaking changes to support World ID 4.0 like RP context and signatures. However, IDKit v4 is backward compatible with World ID 3.0, in this page we document the path of migrating smoothly.
</Note>

## What changed

1. **RP context is required**: Requests now require `rp_context` (`rp_id`, `nonce`, `created_at`, `expires_at`, `signature`).
2. **Old `VerificationLevel` is replaced by presets**: Use legacy presets such as `orbLegacy`.
3. **IDKit response changed**: You no longer need to reshape the payload or compute `signal_hash` for the verify endpoint.
4. **Backend verification endpoint changed**: Use `POST /api/v4/verify/{rp_id}`.

## Migration checklist

- [ ] Enable World ID 4.0 for your app in Developer Portal
- [ ] Upgrade SDK package(s) to v4
- [ ] Generate RP signature from your backend
- [ ] Replace `VerificationLevel` with a legacy preset
- [ ] Move backend verification to `/api/v4/verify/{rp_id}`

## Step 1: Upgrade your app in Developer Portal

If your app was created before v4, open your app in the [Developer Portal](https://developer.world.org) and click the **Enable World ID 4.0** banner. After enabling, keep these values:

- `app_id`
- `rp_id`
- `signing_key` (server-side secret)

## Step 2: Upgrade SDK dependencies

Use the package that matches your stack:

## Step 3: Map `VerificationLevel` to legacy presets

Verification level used to return the maximum available verification level, where if a user had `document` and `orb` credential IDKit would return `VerificationLevel.Orb`. Legacy presets work the same way.

| IDKit `<4` value | IDKit v4 equivalent `Preset` | Notes |
| --- | --- | --- |
| `VerificationLevel.Orb` | `orbLegacy` | Orb-only behavior |
| `VerificationLevel.SecureDocument` | `secureDocumentLegacy` | Secure Document or Orb |
| `VerificationLevel.Document` | `documentLegacy` | Document, Secure Document, or Orb |
| `VerificationLevel.Device` | `deviceLegacy` | Device or Orb  |

## Step 4: Generate RP signature in your backend

Generate request signatures server-side only.

<CodeGroup title="Generate RP context signature">
```ts title="JavaScript"
import { signRequest } from "@worldcoin/idkit/signing";

const { sig, nonce, createdAt, expiresAt } = signRequest(
  "my-action",
  process.env.RP_SIGNING_KEY!,
);

const rp_context = {
  rp_id: "rp_xxxxx",
  nonce,
  created_at: createdAt,
  expires_at: expiresAt,
  signature: sig,
};
```

```go title="Go"
import (
	"os"

	"github.com/worldcoin/idkit/go/idkit"
)

sig, err := idkit.SignRequest(os.Getenv("RP_SIGNING_KEY"))
if err != nil {
	// handle error
}

rpContext := map[string]any{
	"rp_id":      "rp_xxxxx",
	"nonce":      sig.Nonce,
	"created_at": sig.CreatedAt,
	"expires_at": sig.ExpiresAt,
	"signature":  sig.Sig,
}
```
</CodeGroup>

### Step 6: Handle new IDKit response

IDKit returns 3.0 or 4.0 proofs, depending on the initiated flow. 
- Legacy presets will **only** return World ID 3.0 proofs.
- The `signal_hash` is included in the response for convenience, where before you had to hash the signal yourself, that's still an option using `hashSignal` utility.

## Step 5: Adopt `/v4/verify` endpoint 

The [v4 endpoint](/api-reference/developer-portal/verify) accepts both:

- Legacy 3.0 proofs (`protocol_version: "3.0"`)
- 4.0 uniqueness/session proofs (`protocol_version: "4.0"`)

Instead of using `verifyCloudProof` utility you can call the endpoint by copy-pasting the idkit response:


```typescript title="app/api/verify-proof/route.ts"
import { NextResponse } from "next/server";
import type { IDKitResult } from "@worldcoin/idkit";

export async function POST(request: Request): Promise<Response> {
  const { rp_id, idkitResponse } = (await request.json()) as {
    rp_id: string;
    idkitResponse: IDKitResult;
  };

  const response = await fetch(
    `https://developer.world.org/api/v4/verify/${rp_id}`,
    {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify(idkitResponse),
    },
  );

  const payload = await response.json();
  return NextResponse.json(payload, { status: response.status });
}
```
